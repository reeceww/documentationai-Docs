## What it is

A read-only REST API over your workspace. Nine endpoints, all `GET`, served from the app itself rather than a separate host:

```
https://app.hotlineugc.com/api/v1
```

There is no `api.hotlineugc.com`. If you have an older note pointing at one, it was never real.

<Callout kind="info">
  The API and the [MCP server](/api-reference/mcp) are two doors onto the same services. Anything one can read, the other can. Pick the API for scripts and pipelines, and MCP for an assistant.
</Callout>

## What it covers

| Area | What you can read |
|---|---|
| Workspaces | The workspaces your credential reaches, and your role in each |
| Brand context | The workspace's own description of itself, for grounding a model |
| Creators | Your roster and their terms |
| Content | Submissions, their status, and a single creative in detail |
| Analysis | What the creative intelligence pass found on one version |
| Performance | Spend, delivery and revenue per creative |
| Royalties | What has accrued, and against which terms |
| Jobs | The state of a background job |

## What it does not do

**Nothing writes.** Every endpoint is a `GET`. You cannot approve a video, publish an ad, start a pay run or change terms through the API. Money and publishing stay in the app on purpose.

**It is brand side only.** Creator accounts are refused. The data model exists to serve creators too, and a creator-facing surface is a real future feature, but lowering the role floor on the endpoints that exist would hand a creator other creators' deals and the whole royalty ledger.

**There are no webhooks yet.** Hotline receives them from Shopify and Stripe; it does not send them.

## Request shape

Every request carries a bearer token. See [Authentication](/api-reference/authentication).

```bash
curl https://app.hotlineugc.com/api/v1/workspaces \
  -H "Authorization: Bearer hl_live_..."
```

List endpoints take `limit` and `offset`, and answer with `has_more` so you know whether to ask again.

```bash
curl "https://app.hotlineugc.com/api/v1/workspaces/$WORKSPACE/content?limit=50&offset=0" \
  -H "Authorization: Bearer hl_live_..."
```

## Errors

Every failure returns the same JSON envelope, never an HTML error page.

```json
{
  "error": {
    "code": "plan_required",
    "message": "The Hotline API is on Growth and Agency.",
    "request_id": "req_..."
  }
}
```

Branch on `code`, which is stable. The `message` is for a human reading a log, and `request_id` is what to quote if you contact us. It is also returned on success, as the `X-Request-Id` header.

| Code | Status | Meaning |
|---|---|---|
| `invalid_request` | 400 | The parameters did not validate |
| `unauthorized` | 401 | No credential, or one that is not recognised |
| `plan_required` | 402 | The credential is valid, the plan does not carry the API |
| `forbidden` | 403 | Valid credential, insufficient access to this workspace |
| `not_found` | 404 | No such record, or none your credential can see |
| `conflict` | 409 | The request contradicts the current state |
| `rate_limited` | 429 | More than 120 requests in a minute |
| `internal` | 500 | Our fault. Quote the `request_id` |

<Callout kind="info">
  402 rather than 403 for a plan problem is deliberate. It lets a consumer tell an upgrade from a permission problem without reading prose.
</Callout>

## Rate limit

120 requests per minute. Exceeding it returns `rate_limited` rather than dropping the connection.
